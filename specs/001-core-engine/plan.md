# Implementation Plan: ContractAgent Core CEL Invariant Engine & AST Parser

**Branch**: `001-core-engine` | **Date**: 2026-09-23 | **Spec**: [specs/001-core-engine/spec.md](file:///Users/stefano/Documents/contract-agent/specs/001-core-engine/spec.md)

**Input**: Feature specification from `/specs/001-core-engine/spec.md` with integrated clarifications.

## Summary

Implement the foundational data models and deterministic runtime guard for ContractAgent:
1. Pydantic V2 AST parser for `agent.contract.yaml` with static CEL syntax & parameter schema validation at load time.
2. Deterministic CEL (Common Expression Language) evaluation environment with registered extension functions (`workflow.has_approval`, `workflow.called_before`, `workflow.call_count` with overloaded signatures).
3. Zero-LLM property-based fuzzing utilities using `hypothesis` with automatic JSON Schema strategy derivation and custom override hooks.
4. Fail-closed `GuardInterceptor` runtime decorator that wraps tool executions and dispatches `raise_invariant_violation` (`InvariantViolationError`), `block_tool_call` (blocked payload dictionary), and `require_escalation` (`EscalationRequiredError`).
5. Automated Rogue Mutant test fixture verifying 100% fail-closed trapping across numerical overages, sequence skips, and missing approval tokens in CI.

## Technical Context

**Language/Version**: Python 3.11+ (with strict typing enforced by Pyrefly and mypy)

**Primary Dependencies**:
- `pydantic>=2.7.0`: Schema validation & AST definition
- `cel-python>=0.5.0`: Non-Turing complete expression evaluation
- `pyyaml>=6.0.0`: Contract file parsing
- `hypothesis>=6.100.0`: Zero-LLM property-based boundary fuzzing
- `pytest`, `pytest-asyncio`: Automated test harness

**Storage**: In-memory `WorkflowContext` tracking execution history and approval tokens, with SQLite persistence interface for durable asynchronous state transitions.

**Testing**: Pytest unit tests, Hypothesis property tests, automated mutation fixture.

**Target Platform**: macOS (Apple Silicon / Intel), Linux x86_64/arm64.

**Project Type**: Python library & CLI core engine.

**Performance Goals**: < 1ms per CEL invariant evaluation; < 2s for 500 Hypothesis fuzz iterations.

**Constraints**: Zero LLM involvement in Phase 1 invariant evaluation; 100% fail-closed on any error or missing token.
